# 居民楼屋顶光伏认购发电结算与维修平台

面向社区分布式屋顶光伏项目的全生命周期管理平台，覆盖 **建档 → 楼栋表决 → 认购缴费 → 施工排期 → 并网验收 → 发电计量 → 月度收益结算 → 长期运维**，
把住户认购份额、公共账户、补贴、发电量、电价、维修基金、退款与房屋转让串联成清楚的账目与责任边界。

技术栈：**React 18（Vite）+ Go 1.22（chi / pgx）+ PostgreSQL 15**。前端构建产物通过 `go:embed` 打入后端，**单镜像、单容器 + 一个数据库容器即可运行**。

---

## 一、一键启动（Docker Compose）

前置：已安装 Docker 与 Docker Compose 插件。

```bash
cd /workspace/140-feature-1-a
docker compose up -d --build
# 浏览器打开
#   http://localhost:8080
```

首次启动会自动：
1. 创建 PostgreSQL 15 数据库并执行数据库迁移（`backend/internal/db/migrations/0001_init.sql`）；
2. 灌入演示数据（2 个楼栋：1 个已在运营含 8/9 月已定稿结算，以及 1 个 10 月雨后顶楼漏水投诉+收益冻结待释放场景；1 个处于表决阶段）。

停止与清理：

```bash
docker compose down          # 停止
docker compose down -v       # 停止并删除数据库卷（清空全部数据）
```

## 二、本地开发启动（不使用 Docker）

需要本机具备 Go 1.19+、Node 18+、PostgreSQL 14+。

### 1. 准备数据库

```bash
createdb -h 127.0.0.1 -U postgres pvplatform
```

```bash
cd backend
export DATABASE_URL='postgres://用户名:密码@127.0.0.1:5432/pvplatform?sslmode=disable'
export JWT_SECRET='dev-secret'
export SEED_ON_START=true
```

后端启动时自动执行迁移并写入演示数据；同时内嵌前端构建产物（`internal/web/dist`），直接访问 http://localhost:8080 即可。


## 四、功能与业务规则

### 项目建档与阶段流转
- 建档记录屋顶面积、朝向、承重评估、遮挡、产权关系、公共收益规则（含维修基金计提比例）、并网条件、施工影响。
- 六个阶段：`立项建档 → 楼栋表决 → 认购缴费 → 施工排期 → 并网验收 → 发电运营`。
- 阶段可因**顶楼漏水担忧、维护通道、收益质疑、设备供应延迟、电网并网时间变化**回退调整，但**回退必须填写原因**并留痕（阶段日志）。
- 进入认购阶段前必须有一张**同意 ≥ 三分之二住户**的已通过立项表决。

### 认购与缴费
- 住户可认购组件比例（按块计价），或选择**只参与公共收益分配**（不出资）。
- 认购超额会被拦截；缴费后认购款进入公共账户台账。
- 并网验收前可由物业办理**退购退款**，退款生成 payments + ledger 流水。

### 发电计量与异常
- 按逆变器分表或楼总表录入月度发电量，同月可覆盖更新。
- 逆变器可标记故障/恢复；任何住户可上报发电异常，物业填写解释（限电、检修、遮挡、设备故障等）。

### 维修工单与责任判定
- 工单关联结算月份与设备，支持漏水、逆变器故障、维护通道等类型。
- 责任方：物业 / 安装商 / 业主 / 保险 / 多方按比例分担（shared）/ 待判定。
- **物业、业主责任**的维修费先由维修基金支付，不足部分按组件比例在住户与公共部分间分摊；
  **安装商、保险责任**由对方赔偿，不冲减住户收益；
  **多方按比例分担（shared）**：施工方/保险比例计赔偿，基金/公共/业主比例进维修分摊。
- 月度结算定稿后，该月工单的费用与责任锁定，不可再改（防止账目被篡改）。

### 顶楼漏水投诉处置与收益冻结
顶楼住户在雨后投诉新装光伏支架位置渗水时，平台把处置全过程串成留痕链路：

1. **证据归集**：维修工单关联现场渗水照片、**施工照片、屋顶防水验收、雨量记录**，并自动核查**该住户此前是否签署屋顶使用同意书**（同意书可在平台登记/查询，编号留痕）。
2. **责任暂无法确认时的处置**：平台先安排**临时止水、住户安抚、第三方检测**（机构、结论均记录在工单），维修期间不急于向住户分摊费用。
3. **相关组件收益暂时冻结**：物业可按月份、按相关组件对象（认购住户，可只冻其中一部分比例；也可含公共部分）创建收益冻结单；该月结算定稿时，**冻结部分不计入住户余额**（结算明细显示"应分得 / 冻结 / 实入账"），冻结单由"待生效"转为"冻结中"。
4. **责任确认后按比例释放**：第三方检测/责任结论明确后，按 **施工方赔付（compensation）/ 运维基金（维修基金，不足由楼栋公共收益兜底）/ 楼栋公共收益支付 / 业主自负** 的比例释放冻结收益——非业主自负部分返还住户余额，业主自负部分从冻结收益中扣减；施工方赔偿同步登记收付款与台账。
5. **处理结论写入后续屋顶巡检计划**：保存责任结论时自动生成一条 30 天后的屋顶防水复查计划（支架穿层/卷材搭接/雨水管口），可登记巡检结果；也可手工新增巡检。
6. 存在**冻结中（未释放）**收益的认购，禁止办理房屋转让/退购，避免责任与账目随房产转移。

> 操作入口：楼栋详情「**漏水处置/收益冻结**」页签；结算明细在「月度结算」页查看冻结列；冻结/释放流水在「账目台账」页（类别：漏水冻结/冻结释放返还）。


### 月度结算（核心算法，见 `backend/internal/settlement/engine.go`）
1. 发电收入 = 实际发电量 × 上网电价；补贴 = 发电量 × 度电补贴；
2. 运维费、税费按组件比例在认购住户与公共部分间分摊；
3. 维修净支出（责任费用 − 赔偿，先动用维修基金）按组件比例分摊；
4. 公共部分净收益按楼栋规则（默认 20%）计提维修基金，其余为公共可支配收益；
5. 生成每户明细行；物业**试算 → 核对 → 定稿**，定稿后自动：计入住户 `balance`、登记公共账户与维修基金流水、写收付款记录。
6. 碳减排按华东电网排放因子 0.5810 kgCO₂/kWh 估算展示。

### 房屋转让 / 退购
- 权益**随房转移**：认购过户给新业主；历史月份已结算收益归原业主，后续月份按新份额分给新业主。
- 权益**不转移**：按退购处理，退还认购款。
- 办理前系统强制校验：存在未定稿月度结算时拒绝办理，保证**历史收益先结清**。

### 公共治理
- 楼栋公告（可置顶）、住户**异议投票**（同意多于反对即异议成立）、发电异常解释公示、**年度收益报告**（年度发电、收支、住户分成、维修记录、碳减排，物业发布后全楼可查）。
- 楼栋驾驶舱：累计发电、收入、补贴、公共账户、维修基金、待处理工单、月度收益走势、碳减排。
